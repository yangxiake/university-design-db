# 下一阶段完善计划

计划日期：2026-10-02。状态：待实施。

基线提交：`7c1fe1d5493c4f30535cec7c2c1c48cf396e972f`。本计划根据当前档案、索引和覆盖报告制定，里程碑完成后更新实际结果。

## 目标

让个人和AI助手能够按学校身份找到适合PPT的标识、配色、模板与介绍资料，并看到每项资料的来源、用途及可用状态。下一阶段集中提高证据覆盖率、素材选择便利程度和维护质量。

范围采用教育部2026普通高校名单中的全部1412所本科院校，包含普通本科、职业本科、民办及合作办学；军校不额外纳入。新增资料继续标为`verified: auto`，当前阶段采用自动采集验收。

## M1：统一质量校验

### 工作内容

- 将现有档案校验、单元测试、五类生成一致性检查和仓库差异检查整理为统一入口。
- 核对Python及依赖的实际兼容范围，使本地环境与CI环境能执行同一组命令。
- 增加GitHub Actions，在提交、PR及手动触发时运行；默认校验已有数据，联网采集另行运行。
- 补充机器可执行的字段约束：身份唯一、来源必填、日期和统计口径、颜色方法、文件结构状态以及官方/社区标记。
- 校验输出按学校标识码和字段路径定位；保留当前自定义校验器对语义和跨字段关系的检查。

### 验收

1. 1412份档案与本科范围表逐一对应；现有88项测试及必要新增测试通过。
2. 刻意引入身份重复、无来源正向事实、RGB/HEX不一致及过期索引时，检查能够失败并指出位置。
3. GitHub实际运行结果可查看；只配置工作流文件不计作完成。
4. 检查过程不修补事实或覆盖人工选择；正常运行后工作目录无意外变更。

GitHub支持以仓库事件或手动操作触发工作流，文件置于`.github/workflows`。实现参考[GitHub工作流文档](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows)。

## M2：PPT精简数据导出

### 工作内容

新增从单校`profile.yaml`派生的PPT专用导出，候选文件名为`indexes/ppt-profiles.jsonl`及配套CSV；完整档案和既有索引继续作为事实与追溯依据。

精简记录包括：学校标识码、校名、地区、官网、标识候选、配色、模板入口、短简介/校训/建校年引用，以及原档案路径。每条事实和资源携带来源、采集日期、状态及必要使用说明。

- **标识选择**：给出类型、横竖/语言/颜色版式、实际读取状态、格式、透明和矢量信息、来源与选择理由。纯校徽、纯校名、组合图和构成待核验的页头图分别显示。
- **颜色选择**：官方数字色、印刷色、图片取色和社区主题分别保存。仅印刷标准色的屏幕值为空；颜色冲突保存候选。参考色明确给出用途和依据。
- **模板选择**：区分学校通用、院系专用和社区资源，说明PPTX、Marp及Beamer格式；页数和画幅只来自实际文件读取。
- **空缺处理**：身份保留，素材缺项显示原因和查阅状态。推荐理由只根据已记录证据生成。
- **读取体验**：提供按学校标识码读取单校、按省份筛选、按素材状态筛选的示例。导出结构单独版本化。

### 验收

1. JSONL与CSV均可读取，覆盖1412个唯一标识码；导出中的正向事实可回到原档案来源。
2. 学校更名/别名用于检索，不建立重复学校记录；旧名资源保持历史或未确认状态。
3. 官方RGB、仅CMYK、颜色冲突、灰色/反白图、压缩包成员、访问失败和无素材场景都正确表达。
4. 重新生成相同版本数据时结果一致，既有消费者所需字段兼容。

## M3：素材检索与预览

### 工作内容

从PPT精简导出生成轻量目录，支持按校名、标识码、地区和标签检索，再按资源类型、来源、格式、透明信息与读取状态筛选。

- 每校集中显示标识版式、配色色卡、模板格式与官方/社区来源。
- 白色或反白标识提供深色背景预览选项；黑色及彩色图提供合适的展示背景。背景选择与学校标准色分别记录。
- 远程图形使用原来源链接，缩略图的本地保存按明确的图形授权范围处理；本库仍以链接与元数据作为交付主体。
- 无法内嵌预览的文件提供来源入口；校内认证、云盘条件和未读取文件的状态直接显示。
- 图形预览和文件结构检查分开记录。PPTX页数、画幅和声明字体已知时展示；逐页缩略图需实际渲染后才标为已预览。
- 首先验证有代表性的边界场景，再以同一生成器覆盖全部1412所学校。

### 验收

可从检索结果进入某校、比较版式、看到色值方法、定位原来源和模板条件。手机与桌面均可读；远程图形失效不影响文字信息。预览状态、版本依据和使用许可分别显示。

## M4：有针对性的补采

### 优先级

1. 调查中央美术学院配色缺口，并补查144所双一流学校尚缺的官方VI数字证据；仅印刷值与无数字证据的情况按实际记录。
2. 针对198所缺标识学校，优先结合已确认官网、当前校名与有效开源整理来源寻找具体文件。
3. 针对344所缺配色学校，先找校方VI，再检查可用标识；采样值作为设计参考，保留已有标准色或冲突。
4. 继续读取实际PPTX、公开压缩包内模板和明确的发布页；补充学校/院系适用范围、画幅、字体声明及版本标签。
5. 对241所尚未确认官网学校，结合教育部门、现行章程、学校公开公告及已记录候选核对当前主站，避免错误域名和母校误归属。

每批按缺口队列开展，记录来源版本、哈希及实际访问结果；错误可尝试普通公开的不同入口。更名暂停、身份不符、验证页和访问限制分别留账。学校短简介等PPT内容字段随同校可靠证据补充。

### 验收

发布本批前后覆盖变化和未解决问题，分别统计入口存在、文件读过、可预览、官方标准色及参考色。覆盖率目标由实际证据决定，空值按真实调查状态保留。

## M5：自动采集版本交付

### 计划包结构

```text
release-package/
  README.md                  快速开始、版本和自动采集说明
  data/                      PPT精简JSONL、CSV及可选完整档案导出
  indexes/                   分类、标识、配色与模板索引
  docs/                      字段、来源、覆盖率与使用说明
  licenses/                  原创及纳入数据的独立第三方许可
  source-manifest.yaml       范围、输入版本与来源政策
  package-manifest.json      导出版本、对应提交及实际数量
  SHA256SUMS                 交付文件校验值
```

版本按现有标签递增，在现有私有仓库交付明确标注自动采集阶段的预发布版本；Git标签、下载包与变更说明对应同一提交。包中保持来源与独立第三方许可，图形、字体及模板按原来源条件获取。

### 验收

- 在干净目录解包后，依文档完成一次按校取资料和校验。
- 下载包、清单、学校数量、覆盖率及哈希一致；不带本地绝对路径、缓存、凭据或原网页全文。
- 发布说明列出新增数据、结构变更、剩余缺口和兼容性。
- 使用当前`--automatic-draft`验收；自动采集版本的来源与校验结果如实说明，人工审定状态按实际字段标记。

GitHub发布版本基于标签，可附带发布说明和下载文件；参考[GitHub发布文档](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

## M6：来源状态与变更维护

建立手动触发的检查入口，按批次抽查官网、VI页、标识文件和模板入口，保存最终地址、HTTP/解析结果、读取日期及内容变化线索。

单次网络失败只记录状态，历史成功证据保留；重复失败或身份变化进入更新队列。页面哈希变化是重新查证线索，事实更新需核对具体内容。新旧来源、学校名称延续关系与被替代记录都可追溯。

验收须覆盖暂时超时、永久失效候选、合法重定向、跨学校跳转和更名场景；检查报告能区分仍可使用的历史记录与需要重新取证的字段。

## 最先实施的一批

首批实施M1与M2：统一本地/CI校验、生成1412所PPT精简数据、验证标识与配色选择的边界场景。完成后提交代码、实际运行结果及字段样例，再推进M3的素材目录与预览。M4持续提供有来源的补采数据。

借鉴方向：[Hipo](https://github.com/Hipo/university-domains-list)的简洁机器读取、[ROR](https://github.com/ror-community/ror-schema)的版本化字段约束、[SVGLOGO](https://github.com/HeyHuazi/SVGLOGO)的资产/元数据一致性，以及[北京高校VIS目录](https://github.com/CakeAL/beijing-univs-vis)对格式和访问条件的明确表达。已纳入来源的字段映射见[字段比较报告](github-field-union-2026.md)与[第三方来源说明](../data/external/README.md)。
